# Flipkart E-commerce Decision Intelligence (capstone, synthetic data)

All data are synthetic (generated by `generate_data.py`); nothing here reflects Flipkart's real data or performance. Money is in INR. Values in the `value` column are in hundreds of INR (8.0 = INR 800).

## How to run

From a clean clone, in this order:

```
pip install -r requirements.txt
python generate_data.py        # prints: 800 10 170 c6f249ba693f1ebeed318d6d5e18de23
python part1.py
python part2.py
python part3.py
python part4.py
```

`common.py` holds code shared by Parts 2 and 4 (split, logistic regression, KNN, metrics); importing it runs nothing. Every number below is copied from the files in `outputs/`.

## Part 1 findings

**R1.1 Hypothesis test.** H0 (mean = 8.0) is **rejected**: z_stat = 2.8930, which is above the critical value 1.96. A Type I error here would mean concluding that the true average order value differs from INR 800 when it really equals INR 800, and so changing category plans for no reason. The gap is mean_value − 8.0 = 8.9382 − 8.0 = 0.9382 units, about INR 94 (the 95% interval is 8.3026 to 9.5738, i.e. INR 830 to INR 957). I think it matters in practice: the planning figure is roughly 12% too low, and the whole interval lies above INR 800. Order values are very spread out (sd_value = 9.1723), so the mean is pulled up by a few large orders.

**R1.2 Sample size.** n_required = 1293 orders are needed for a margin of error of 0.5 units (INR 50) at 95% confidence, but only 800 rows are available. With 800 rows the margin is about 0.64 units (1.96 × se_value = 1.96 × 0.3243), so the team would need about 493 more orders for the INR 50 precision.

**R1.3 Gradient descent.** gd_slope_gap = 0.0000 (below 0.001). The squared-error cost is a single smooth bowl with one minimum, and with a standardised X4 and η = 0.1 the steps settle there (gd_J100 = gd_J500 = 40.3698), which is where the closed-form formula lands.

**R1.4 Funnel.** resid_sd_ratio_raw = 3.7525: the raw model has a clear funnel (residual spread in the upper half of fitted values is almost four times that of the lower half). resid_sd_ratio_log = 1.0396: the log-log model removes it (the two halves have almost the same spread).

**R1.5 Multiple regression.** The predictors with |coefficient| > 0.05 are ln(X4) (mr_beta_1 = 1.1576), X2 complaints (0.0940), X3 discount share (0.1067) and X6 cod_flag (0.1518). This is a mechanical rule on coefficients in different units, not a ranking of importance. mr_adj_r2 = 0.7403 against loglog_adj_r2 = 0.6561: the extra predictors raise adjusted R² by about 0.084, so they earn their place.

## Part 2 findings

Split: train_rows = 560 (119 positives), test_rows = 240 (51 positives).

**R2.1 Learning rates.** After 200 updates the losses are 0.3703 (η = 1.0) < 0.3776 (η = 0.1) < 0.5091 (η = 0.01): a learning rate that is too small is still far from the minimum, while the large one got there fastest on this well-scaled data (a large rate can still overshoot on other problems).

**R2.2 Weights.** The three largest absolute weights are X3 discount share (0.9013), X1 tenure (−0.5554) and X2 complaints (0.5505). The largest odds ratio is odds_ratio_X3 = 2.4629: each extra training standard deviation of discount order share multiplies the odds of churning by about 2.5, other things equal.

**R2.3 Accuracy and threshold.** blind_accuracy = 0.7875 (predict "stays" for all) versus tau_0.5_accuracy = 0.8042: a model that never finds a single churner scores almost as well, so accuracy hides what matters. Lowering τ from 0.5 to 0.3 raised recall from 0.4706 to 0.7451 (tp 24 → 38) and lowered precision from 0.5455 to 0.4634.

**R2.4 Logistic vs KNN.** Logistic at τ = 0.3 has f1 = 0.5714 and recall = 0.7451; KNN (K = 5, chosen by cross-validation) has knn_f1 = 0.3696 and knn_recall = 0.3333. Logistic is clearly better.

**R2.5 Deployment.** I would deploy the logistic model at τ = 0.15, the threshold with the lowest training cost (cost_train_at_tau = INR 12,150). On the test rows the cost is cost_test_at_tau = INR 6,050, against cost_test_at_0.5 = INR 11,800 and cost_test_flag_nobody = INR 20,400. The threshold was chosen on training rows so that the test rows stay an untouched, honest estimate; tuning τ on them would make the test cost optimistic.

## Part 3 findings

**R3.1 Elbow.** WCSS drops: WCSS(2) − WCSS(3) = 659.8282; WCSS(3) − WCSS(4) = 108.0739; WCSS(4) − WCSS(5) = 171.0575; WCSS(5) − WCSS(6) = 45.5466. elbow_k = 3: after K = 3 the next drop (108.07) is below half of the previous drop (329.91). The drops do not shrink steadily (171.06 > 108.07 for K = 4 to 5), because the pinned starting rows give one reproducible solution, not necessarily the global optimum.

**R3.2 Segments** (from `part3_segments.csv`):

| Segment | Size | Profile | Name | Action |
|---|---|---|---|---|
| A | 322 | tenure 47.5 months, discount share 0.225, loyalty 62.2, outcome_rate 0.0186 | Loyal full-price regulars | No coupon; keep them with loyalty perks and early access |
| B | 255 | 6.07 complaints, highest average order value (28.7 = INR 2,870), mean_value 17.1, outcome_rate 0.2353 | High-spend but unhappy (premium) | Fix service issues first; personal outreach by an account manager |
| C | 223 | tenure 14.4 months, discount share 0.7118, loyalty 38.5, outcome_rate 0.4664 | Bargain-focused newcomers | Targeted retention coupon, since this group churns most |

The highest outcome_rate is segment C at 0.4664. A is the quietest segment (outcome_rate 0.0186); the numbers do not show a seasonal group.

**R3.3 Linkage.** Single linkage cuts into 4 clusters: {E2, E3, E6}, {E1}, {E4}, {E5}. Complete linkage cuts into 2 clusters: {E1, E4, E5} and {E2, E3, E6} (average linkage also gives 2). Single linkage only looks at the closest pair, so groups chain together by small steps and its largest gap falls early (merge 2 at 1.4 to merge 3 at 2.8), while complete linkage looks at the farthest pair, so the last merge happens at 7.9, a huge gap that clearly separates the two halves.

**R3.4 PCA.** The mean vector is all zeros after standardising. PC1 (explained_ratio_1 = 0.5227) contrasts tenure (+0.5317) and loyalty score (+0.4418) against discount share (−0.5187), complaints (−0.4100) and average order value (−0.2916). components_for_80pct = 3 (cumulative ratio 0.7593 with two, 0.8616 with three). mean_pc1_segment_A/B/C = 1.7773 / −0.7831 / −1.6709: PC1 orders the segments from loyal long-tenure (A) to discount-driven newcomers (C), the same order as their outcome rates.

## Part 4 findings

**R4.1 Best split.** S4 (X1 ≤ 24 months) has the highest information gain (0.1252) and Gini gain (0.0606): the 188 customers on its yes side are 45.7% positive (stump_rate_yes = 0.4574) versus 8.9% on the no side (stump_rate_no = 0.0887), so it separates churners most cleanly. A tree grown until every leaf is pure would memorise noise in individual training rows and overfit. A limit on depth (maximum depth, or a minimum number of rows per leaf) stops it.

**R4.2 Models.** On the test rows, f1 / recall are: logistic 0.5714 / 0.7451, knn 0.3696 / 0.3333, stump 0.5532 / 0.7647, hard_vote 0.5344 / 0.6863, soft_vote 0.5507 / 0.7451. I would ship the logistic model. Combining did not help: neither vote beat the logistic model alone, because the weak KNN vote pulls the combination down.

**R4.3 AdaBoost.** After round 1 the two misclassified points (3 and 7) have total weight 0.5000 (0.25 each). Round 2 trusts h2 more (round2_alpha = 0.8047 versus round1_alpha = 0.5493) because its weighted error is lower (0.1667 versus 0.2500). ensemble_accuracy = 0.7500.

**R4.4 Architecture.** oob_fraction = 0.3676.

cnn_total = 15,734; mlp_total = 13,002 (option 1: 12,560 + 272 + 170). A flattened 128 × 128 × 3 input into 1,024 neurons needs fc_layer_params = 50,332,672 parameters, while 64 filters of 3 × 3 on the same input need only conv_layer_params = 1,792, because a filter's weights are shared across all positions.

Model B (recurrent network): W_xh is 128 × 64, W_hh is 128 × 128, W_hy is 16 × 128; rnn_total = 26,768. It does not grow with longer sequences because the same weights are reused at every step.

Activations: ReLU in the hidden layers; softmax at the output with categorical cross-entropy loss for the 10 classes.

Very deep plain networks stop learning in early layers because backpropagation multiplies many derivatives that are often below 1, so the gradient shrinks towards zero as it travels back (vanishing gradient). A skip connection adds the layer's input to its output, giving the gradient a direct path back that does not shrink.

## Model-choice memo

**To:** Head of the Retention Team

**Recommendation:** put the logistic-regression model into production with an alert threshold of τ = 0.15.

On 240 held-out customers (51 real churners) this setting costs INR 6,050 under our cost rule (INR 50 per wasted coupon, INR 400 per missed churner). That compares with INR 11,800 at the default 0.5 threshold and INR 20,400 if nobody is flagged (`part2_results.txt`). The threshold was chosen on training rows only, where its cost was INR 12,150.

Among the structured models, logistic is the strongest: at τ = 0.3 it reaches recall 0.7451 and f1 0.5714, ahead of KNN (recall 0.3333, f1 0.3696) and ahead of both voting schemes (f1 0.5344 and 0.5507) in `part4_voting.csv`. I did not compute INR costs for the other models with the Task 2.8 rule, so I only report the logistic cost.

**Limitation:** the evidence comes from synthetic data, one fixed split and only 51 positive test customers, so the INR 6,050 figure could move noticeably on fresh data. The INR 50 and INR 400 costs are also rough estimates.

Neither the image model (Model A) nor the review-text model (Model B) is worth building before the structured model is in production, because no picture or text data have been collected and the structured model already answers the churn question.

## Limitations

1. The data are synthetic and generated from a known formula, so the results say nothing about real customer behaviour, and real data would be messier.
2. There is a single fixed 560/240 split; the best K (5) and the threshold (0.15) are valid for that split only, and other splits could change them.
3. The test set has only 51 positive customers, so recall, f1 and cost figures are noisy (one customer changes recall by about 0.02).
4. K-means uses fixed starting rows, so the segments are one reproducible solution, not necessarily the best; K = 3 was fixed by the brief.
5. The INR 50 and INR 400 costs are rough assumptions; a different cost ratio would move the best threshold.
6. Hierarchical clustering uses a small supplied table of only six cohorts, so the cuts are illustrative.
